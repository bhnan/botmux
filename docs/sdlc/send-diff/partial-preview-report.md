# 超限 diff 部分预览修订报告

## 范围

需求讨论中反复修改文档时，用户需要看到 Agent 的真实改动。按用户最新要求，超过 2MiB 的 diff 仍展示部分文件/行，并在文件面板底部加一小行灰字说明截断。旧 f724276 完全省略超大 diff 的行为被本地候选版本取代。

生产修改仍集中在 `src/cli.ts`（有界读取和 dry-run）、`src/im/lark/md-card.ts`（解析及共用卡片渲染）、`src/skills/definitions.ts`（技能说明）；没有增加独立生产模块，`send-policy.ts` 的参数策略沿用原实现。

## 缺陷分析与处理

本轮是用户明确要求的展示行为调整。以既有完整输入严格验证为基线，增加只对超大前缀开放的 EOF 容忍，保留已读取的合法差异行；尾部不完整文件头不生成虚假文件，非 EOF 格式错误仍拒绝。

文件通过 FD 读取，最多 2MiB+1 字节用于判定超限，只解码前 2MiB；UTF-8 切口不会产生乱码，FD 在 finally 中关闭。输入大小检查后文件增长同样受读入预算限制。

## 当前展示与统计规则

每文件默认最多 60 行，包含 hunk 定位行；整卡约 18KB 的预览预算可能进一步减少展示行或文件数，灰字使用实际显示行数。长行最多展示前 1024 个 UTF-16 单元，并保留字符边界和省略号。

完整输入：`statsScope=full`，即便显示截断仍保留真实全量计数。超 2MiB 前缀：`statsScope=preview`，文件和增删计数只代表实际展示部分，未知全量省略文件数为 null。灰字为“diff 超限，仅显示前60行（计数仅预览）。”；无可读内容的异常输入前缀才使用最小灰字说明。

2MiB 是解析输入预算，60 行是每文件显示上限；超大输入不会验证未读部分。完整原文件不被修改，完整内容仍按技能流程交付。摘要本身或卡片构建预算出错仍为单行原因、退出码 2、没有成功发送；不会自动生成另一张错误卡。
